## 3. 实施步骤

### 3.1 本地 build + 启动容器


### 3.3 拉 ECS 库到本地（走 fetch_db.py）

**走 API 不走 scp**（ECS 红线）：
```bash
cd C:/Users/Yaojie/Documents/GitHub/quiz
# 拉库前先停本地容器（避免锁文件）
docker stop quiz-local
python scripts/fetch_db.py
# 拉完后看 data/quiz.db 体积 + 时间戳
ls -la data/quiz.db
```

**注意**：
- `fetch_db.py` 是走 ECS 的 `POST /api/admin/exec-sql` 拉数据，**不传 .db 文件**——符合 ECS 铁律
- 拉库前本地如果有学员数据/题目，**会被覆盖**——先确认本地无重要数据
- 拉库后检查 topics 表是否已含新两列（应该没含，因为 ECS 是旧 schema；本地 docker 启动时会自动跑迁移加上）

## 6. 风险提示

- **拉库覆盖本地**：fetch_db.py 拉的是 ECS 库的全量数据，**会覆盖本地所有题目/学员/记录**。如果本地有测试数据或刚改的教程 URL，会被 ECS 的旧数据替换。**建议先在管理端录入一两条 URL → 拉库 → 拉库后 URL 会变 NULL → 在管理端再录一次**。或者：本任务暂不录真实 URL，只验证界面流程。
- **本地 docker 端口冲突**：8000 端口可能已被其他容器占用，必要时改 `-p 8001:8000`。
- **拉库后实操/理论科目分类可能变化**：拉库后 subjects 表的 category 字段是 ECS 的值，确保 study.html 分流逻辑（`isPractical`）仍正确。
