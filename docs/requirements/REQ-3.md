# REQ-3: 课程递进解锁与组题默认值调整

> 状态: ✅已确认 | 优先级: P0 | 提出日期: 2026-08-28

## 需求背景

当前学员可以随意选择任意课程做题，没有递进约束。需要引入"前置课程全部精通才解锁后续课程"的机制，确保学习路径有序。同时调整组题界面的默认行为。

## 需求描述

### 1. 课程递进解锁

- 课程已达 **mastered（精通）** → 不限，随时可答，允许回跳
- 课程 **未达精通** → 检查同科目内 `sort_order` 更小的所有课程，全部精通才解锁当前课
- 未解锁的课程在组题界面显示 **锁定状态**，点击时弹窗提示："先把前面的课程学到精通，再来挑战这一课吧！"

### 2. 组题界面默认值调整

| 项目 | 旧值 | 新值 |
|------|------|------|
| 课程选择 | 默认全选 | 默认选中**最靠前且未精通且已解锁**的一课（单选） |
| 题数档位 | 10题 | **20题** |
| 难度档位 | 1（初级） | 1（初级）不变 |

## 边界条件

| 场景 | 处理 |
|------|------|
| 全部课程已精通 | 默认选中最后一课（无未精通课可选） |
| 第一门课未精通 | 默认选中第一门课 |
| 实操科目 | 同样适用递进解锁 |
| 已精通课回跳 | 允许，不锁定 |

## 验收标准

1. 学员在组题界面看到未解锁课程有锁定图标，点击弹出提示
2. 已精通课程可正常点击选择
3. 默认选中逻辑：最靠前且未精通且已解锁的一课
4. 题数档位默认 20 题
5. 提交组卷 API 侧校验：如果选了未解锁的课，返回错误提示

## 技术要点

- 后端新增接口 `/api/mastery/course-lock-status` 或复用现有 `/api/mastery/me` 返回锁定状态
- 前端 `home.html` 的 `openConfig` 和 `openCoursePick` 中应用解锁逻辑
- 题数档位默认值从 10 改为 20
