# 出题模板规范

> 状态：📝 Draft
> 创建：2026-08-24
> 适用范围：所有科目、所有题型
> 触发时机：每次新增题目入库前，必须逐条过本规范

## 一、题型 × 科目 适用矩阵

| 题型 | 数学 | 语文 | 英语 | Python 理论 | Python 实操 |
|------|:---:|:---:|:---:|:---:|:---:|
| choice（单选） | ✅ | ✅ | ✅ | ✅ | ✅ |
| judge（判断） | ✅ | ✅ | ✅ | ✅ | ✅ |
| **calc（计算）** | ✅ | ❌ | ❌ | ❌ | ❌ |
| match（连线） | ✅ | ✅ | ✅ | ✅ | ✅ |
| sort（排序） | ✅ | ✅ | ✅ | ✅ | ✅ |
| fill（填空） | ✅ | ✅ | ✅ | — | — |
| essay（论述） | — | ✅ | ✅ | — | — |
| reading（阅读） | — | ✅ | ✅ | — | — |
| **code（编程）** | — | — | — | — | ✅ |

**铁律：calc（计算题）只出现在数学科目。**
- 数学 calc：手算输出值，答案必须精确（整数/分数/小数形式固定）。
- Python 理论里"执行代码输出什么"→ 归 **choice**（给选项选输出）或 **code**（实操执行），**不用 calc**。
- 语文/英语无 calc。

## 二、通用条款（所有科目、所有题型）

### G1. 代码/计算强制验证 ⚠️ P0
凡题干含代码或数值计算，`explanation` 必须附验证记录：
```
# 验证: python3 -c "..." → 实际输出
# 验证: 手算过程
```
生成器/入库脚本中实际执行，输出与 `answer` 不一致 → **拒绝入库**。

> 2026-08-24 教训：T39/T40 复核发现 5 题错误，4 题是判断题方向反、1 题连线方向反，全部可通过"跑一遍"拦截。

### G2. 判断题双理由校验 ⚠️ P0
判断题必须同时写出"为什么对"和"为什么错"两条理由，**两条都逻辑通顺才放行**。
- 只有一条通顺 → 题干有歧义，必须改写题干。
- 两条都不通顺 → 题目本身错误，删除。

> 2026-08-24 教训：5750 "lambda 只能有一个参数"——"参数个数"和"表达式结构"两种理解都说得通，双理由校验可拦截。

### G3. match/sort 配对方向显式化
- `content` 必须写明配对方向：如"将【左列概念】与【右列行为】连线"。
- 右列必须**全部同一语义类型**（全是行为 / 全是结果 / 全是代码），禁止混装。
- sort 题必须说明排序依据（按什么排、升/降序）。

> 2026-08-24 教训：4102 "for 循环变量→不外泄"，右列"不外泄"既可读成结论也可读成特性，歧义。

### G4. 干扰项可证伪标注
每个干扰项必须对应一个**具体错误模式**，在 `explanation` 中标注：
```
干扰项 B: 把减法算成加法（x-y → x+y）
干扰项 C: 漏看 reverse=True
干扰项 D: 混淆 sorted() 和 .sort()
```
这能反向检验题目本身没有多解。

### G5. 重复题去重
同一 topic 下，题干相似度 > 0.8 的题对，标记出来人工确认是否保留。
- 简单实现：`difflib.SequenceMatcher` 比值 > 0.8。
- 保留的题必须在 explanation 里注明"与 #xxx 区别在于..."。

> 2026-08-24 发现：T39 中 451/941、452/942 几乎重复。

### G6. AI 逐题模拟答题复核 ⚠️ P0
新增题入库前，必须由 AI 以"学生视角"逐题模拟作答：
- **choice**：逐个排除选项，写出选哪个 + 排除理由
- **judge**：独立判断对/错，写出推理链
- **match/sort**：独立配对/排序，写出依据
- **calc**：手算或跑代码，比对输出
- **code**：实际执行，比对 stdout

输出格式：
```
题 XXXX [题型]
题干: ...
我的作答: ...
标准答案: ...
结论: 通过 / ⚠️ 存疑（原因）
```

存疑题（⚠️）单独拎出给人工裁决，通过的题直接过。

## 三、calc 专属条款（仅数学）

### C1. 答案精确化
calc 答案必须给出**精确形式**：
- 整数：`42`（不写 `42.0`）
- 分数：`3/4`（不写 `0.75`，除非题干要求小数）
- 小数：保留位数在题干中声明（如"保留两位小数"→ `0.75`）
- 带单位：题干有单位则答案带单位（`12 km`）

题干必须标注"请写出精确值"或"保留 X 位小数"，消除歧义。

### C2. 计算过程可追溯
`explanation` 必须写出完整计算步骤，不能只写结果。
```
# 错误: 3×4=12
# 正确: (2+1)×(3+1) = 3×4 = 12
```

## 四、code 专属条款（仅 Python 实操）

### P1. 必须附标准答案代码 + 预期输出
```json
{
  "answer_code": "def f(x):\n    return x * 2\nprint(f(5))",
  "expected_output": "10"
}
```
学生代码与标准答案不同但输出一致 → 判分规则决定（见 P2）。

### P2. 判分规则显式声明
题干或 metadata 中必须写明判分方式，三选一：
- `exact_output`：输出完全匹配（含空格/换行）
- `contains`：输出包含关键词
- `unit_test`：通过附带的单元测试

禁止依赖判分器"猜"。

### P3. 运行环境说明
题干必须声明：
- Python 版本（3.x）
- 是否允许 `import`（哪些模块）
- 是否有 `input()`（纯输出题 vs 交互题）
- 工作目录/文件依赖（如有）

> 2026-08-24 教训：979 "print(list(map(...)))" 如果学生没注意到要 `print`，写成 `list(map(...))` 输出对不上。环境说明里写"纯输出题，结果必须 print"即可避免。

### P4. 错误代码变体可定位
如果 code 题附带"哪段代码有错"的子问，每个错误变体必须对应一个**具体 bug 模式**：
```
错误变体 A: 少写 return（函数返回 None）
错误变体 B: 缩进错误（IndentationError）
错误变体 C: 变量名拼错（NameError）
```

## 五、入库前 Checklist（硬性）

```
[ ] G1  代码/计算已实际执行验证，输出与 answer 一致
[ ] G2  判断题双理由（为什么对 + 为什么错）都通顺
[ ] G3  match/sort 配对方向已写明，右列同语义类型
[ ] G4  每个干扰项已标注对应错误模式
[ ] G5  已查重，无相似度 > 0.8 的未标记重复题
[ ] G6  AI 已逐题模拟答题，存疑题已提交人工裁决
[ ] C1  (数学 calc) 答案形式精确，题干声明精度要求
[ ] C2  (数学 calc) 计算步骤完整
[ ] P1  (Python code) 标准答案代码 + 预期输出已附
[ ] P2  (Python code) 判分规则已显式声明
[ ] P3  (Python code) 运行环境已声明
[ ] P4  (Python code) 错误变体已标注 bug 模式
[ ] 科目-题型矩阵合规（calc 仅数学，code 仅 Python 实操）
```

全部打勾才允许入库。任何一条不过 → 退回修改。
