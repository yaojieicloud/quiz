# BUG-4: 语文/英语 topics.sort_order 全为 0，递进解锁对两科不生效

> 状态: 🔴待修复（已知事项，未排期）
> 发现: 2026-08-29 REQ-3 验收核查（只读实测）
> 关联: REQ-3 课程递进解锁

## 现象

REQ-3 递进解锁在 Python 基础理论、Python 基础实操、数学三科实测生效；但**语文（69 课）与英语（48 课）的 `topics.sort_order` 全部为 0**，前端 `isTopicUnlocked` 与后端 `/api/exam/start` 按「sort_order 更小的课须全部精通」判定，全 0 → 无前置课 → **两科全部课程处于解锁状态、默认选中恒为最靠前一课**，递进约束实际未起作用。

## 根因

历史批数据时语文/英语课时未填写排序号（默认 0）。Python 两科与数学排序正常（0~19 / 0~12 递增）。非代码缺陷，算法行为符合其数据输入。

## 影响

- 学员选语文/英语时可随意跳课（与 REQ-3 设计意图不符），已解锁课程无锁、无拦截。
- 后端校验对两科同样放行（无 400），前后端口径一致，不产生脏数据。

## 建议修复方案（待阿垚确认后执行）

1. 备份 `data/quiz.db`（本地 + ECS 各一份）。
2. 按「年级 → 单元（unit 字段已有）→ 课内顺序（课时名编号）」为 117 条 topics 重排 `sort_order`（同科目内 0 起递增）。排序规则落盘前先给阿垚预览确认。
3. 重排后重跑 REQ-3 验收脚本，确认两科递进生效。
4. 全量部署至 ECS（数据卷在 ECS 侧，需同步处理线上库）。

## 备注

- 语文/英语 unit 字段本身携带「上册-第X单元」「上/下册-Unit N」结构，可作为排序依据。
- 在修复前，REQ-3 验收按「三科生效 + 两科数据受限」收口，不阻塞需求结束。
