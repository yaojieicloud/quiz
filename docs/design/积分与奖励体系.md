> 模块：`routers/reward.py`（学员侧）、`routers/reward_admin.py`（管理侧）、`seed_reward.py`、`models.py`(PointsLedger/ScoringRule/StudentPoints/RedeemItem/WheelPrize/Play/DirectRedemption/MasteryReward)
> 关联：[组卷与答题流程](组卷与答题流程.md)（积分发放）、[部署与运维](部署与运维.md)（seed 幂等）

## 1. 设计原则（来自 `docs/plan/积分系统与大转盘方案.md`）

1. **所有参数可配置**：抽奖费、转盘奖品与权重、直兑价格、积分换算矩阵全部落库，管理员后台编辑，**禁止硬编码**。
2. **概率服务端决定**：抽奖结果后端按权重随机算出，前端只收结果，防篡改。
3. **原子记账**：扣积分与生成记录同一事务，防超抽/并发超支。
4. **通用机制**：大转盘、直兑、未来盲盒共用「消耗积分 → 服务端出奖 → 实物需核销」。

## 4.5 精通奖励（2026-08-24 上线）

> 模块：`migrations/0005_mastery_rewards.py`、`routers/exam.py _award_mastery_rewards`、`models.py MasteryReward`、`static/js/common.js showMasteryRewardPopup`

**机制**：答题交卷后某课被判定为「精通」（非精通→精通跃迁）→ 奖励一次「玩转大转盘」等额积分（**动态读 `config.wheel_cost`**，线上当前 30）→ 前端弹烟花惊喜弹窗。

**触发与发放**（`submit_exam` 同事务，`upsert_student_mastery` 之后）：
1. upsert 前后状态对比，检测本次新达到精通的课（跃迁）；
2. 有新精通才触发：逐条发放（mode=`new`）+ **一次性补发**该学员所有已精通但未发奖的历史课（mode=`retroactive`，补发积分也按发放当时的 `wheel_cost`）；
3. 防重复：`(student_id, topic_id, tier)` 唯一约束 + 发放前查已发放集合；
4. 积分档位（初级/进阶/挑战）独立判定、独立奖励（与掌握度体系一致）；
5. 保护：`wheel_cost <= 0` 时不发放（精通记录保留，费用恢复后随下次触发补发）；
6. 记账：`PointsLedger(reason="mastery_reward", ref_id=mastery_rewards.id)`，与余额同事务。

**前端弹窗**（`showMasteryRewardPopup`，common.js）：canvas 全屏烟花粒子特效 + 恭喜卡片，新达成/补发合并一个弹窗逐条列出「科目 · 课程 · +X积分」（补发蓝色标签），底部合计。交卷后由 `quiz.html` 按 `ExamRecordOut.mastery_rewards` 触发。

**测试入口**：admin 奖励管理页「精通奖励测试」按钮 → `POST /api/admin/test-mastery-reward`（只读）。

## 5. 种子数据（`seed_reward.py`，幂等）

- `SCORING_MATRIX`：题数档位 × 分数段的全局默认积分（2026-08-24 档位化改造后）：
  - 10题：100→1 / 90→1（<90 无规则=0）
  - 20题：100→2 / 90→1（<90=0）
  - 30题：100→3 / 90→2 / 80→1（<80=0）
  - 40题：100→4 / 90→3 / 80→2 / 70→1（<70=0）
  - 50题：100→5 / 90→4 / 80→3 / 70→2 / 60→1（<60=0）
  - 发分查表：先按科目专属（`subject_id` 匹配），再全局（`subject_id IS NULL`）；各自内部先精确匹配 `question_count`，缺则回落 `question_count=0`。无命中=0。
- `SUBJECT_SCORING`：Python基础实操专属（1 题档，100→2 / 90→1），与全局矩阵同一张表、同一套机制。
- ~~旧逻辑~~：`SCORING_MATRIX = [(0,80,3),(0,90,4),(0,100,5)]` delete 后覆盖写 —— 已废除。覆盖写导致管理员后台配置被容器重启重置（2026-08-21 在 `subject_points` 上踩过同款坑）。现改为**仅缺失时写入**（幂等，后台配置不再被重置）。
- `WHEEL_PRIZES`（权重）：谢谢参与30 / 小心愿券18 / 小礼物券17 / 1元15 / 2元12 / 5元8。
- `REDEEM_ITEMS`：小心愿100 / 小礼物200 / 零花钱1元100 / 2元200 / 5元500。
- `CONFIGS`：`wheel_cost=20`、`launch_popup_version=v1`。
- ~~`SUBJECT_POINT_OVERRIDES`~~：已并入 `SUBJECT_SCORING`（走 `scoring_rules` 同一机制），不再写 `subject_points` 表。

entrypoint 启动即 `python seed_reward.py`，保证积分/转盘/直兑配置存在（幂等：已存在不覆盖）。

> Python 实操初阶积分下调为 `100→2 / 90→1 / <90→0`（防小朋友刷积分）；tier 倍率（进阶×2、挑战×3）仍生效。
