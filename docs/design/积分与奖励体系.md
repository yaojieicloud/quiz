# 积分与奖励体系 设计文档

> 模块：`routers/reward.py`（学员侧）、`routers/reward_admin.py`（管理侧）、`seed_reward.py`、`models.py`(PointsLedger/ScoringRule/SubjectPoints/RedeemItem/WheelPrize/Play/DirectRedemption)
> 关联：[组卷与答题流程](组卷与答题流程.md)（积分发放）、[部署与运维](部署与运维.md)（seed 幂等）

---

## 1. 设计原则（来自 `docs/plan/积分系统与大转盘方案.md`）

1. **所有参数可配置**：抽奖费、转盘奖品与权重、直兑价格、积分换算矩阵全部落库，管理员后台编辑，**禁止硬编码**。
2. **概率服务端决定**：抽奖结果后端按权重随机算出，前端只收结果，防篡改。
3. **原子记账**：扣积分与生成记录同一事务，防超抽/并发超支。
4. **通用机制**：大转盘、直兑、未来盲盒共用「消耗积分 → 服务端出奖 → 实物需核销」。

## 2. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `points_ledger` | student_id / delta(正负) / reason(exam_reward/wheel_spin/direct_redeem/admin_adjust) / ref_id / balance_after | 积分流水，唯一真相 |
| `scoring_rules` | question_count(0=任意) / score_band(80/90/100) / points / is_active | 积分矩阵 |
| `subject_points` | subject_id(unique) / p100(默认5) / p90(默认4) / p80(默认3) | 科目积分覆盖 |
| `student_points` | student_id(PK) / balance | 余额快照 |
| `redeem_items` | name / type(virtual/physical) / cost / virtual_payload / is_active / sort_order | 直兑商城 |
| `wheel_prizes` | mode(wheel/blindbox) / name / type / weight / virtual_payload(如"+2积分") / is_active | 转盘奖品池（含权重） |
| `plays` | status(pending/granted) | 抽奖记录（实物 pending 待核销） |
| `direct_redemptions` | status(pending/redeemed/granted) / redeemed_at / redeemed_by | 直兑核销记录 |

## 3. 学员侧接口（`routers/reward.py`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 公开；返回 wheel_cost / launch_popup_version 等 |
| GET | `/api/points/balance` | 当前余额 |
| GET | `/api/points/ledger` | 流水（分页，page_size≤100） |
| GET | `/api/wheel/prizes` | 转盘奖品 |
| POST | `/api/wheel/spin` | 先扣分→服务端 `random.choices` 加权→physical 置 pending / virtual 置 granted 并处理 `+N积分` 载荷 |
| GET | `/api/redeem/items` | 直兑列表 |
| POST | `/api/redeem/direct` | 直兑（扣积分，physical 进待核销） |
| GET | `/api/redeem/mine` | 我的奖品 |

## 4. 管理侧接口（`routers/reward_admin.py`，全部 admin）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/redeem/pending` | 待核销；注入 **student_name**（nickname 优先，缺则 username，兜底 `学员#{id}`） |
| POST | `/api/admin/redeem/approve` | pending→redeemed（非 pending 报 400） |
| GET | `/api/admin/points/ledger?student_id=` | 流水查询 |
| POST | `/api/admin/points/adjust` | 积分调整（调整后余额不得为负） |
| CRUD | `/api/admin/scoring-rules` | 积分矩阵 |
| CRUD | `/api/admin/wheel-prizes` | 转盘奖品（含 **weight**） |
| CRUD | `/api/admin/redeem-items` | 直兑（含 **cost 兑换积分**） |
| GET/PUT | `/api/admin/subject-points[/batch]` | 科目积分批量设分（默认 5/4/3） |
| GET | `/api/admin/llm-calls` | LLM 审计日志 |

## 5. 种子数据（`seed_reward.py`，幂等）

- `SCORING_MATRIX = [(0,80,3),(0,90,4),(0,100,5)]`：每次 seed **delete 后覆盖写**（`seed_reward.py`）。
- `WHEEL_PRIZES`（权重）：谢谢参与30 / 小心愿券18 / 小礼物券17 / 1元15 / 2元12 / 5元8。
- `REDEEM_ITEMS`：小心愿100 / 小礼物200 / 零花钱1元100 / 2元200 / 5元500。
- `CONFIGS`：`wheel_cost=20`、`launch_popup_version=v1`。
- `SUBJECT_POINT_OVERRIDES`：`Python基础实操 → (2,1,0)`。**仅首次创建、已存在则跳过不覆盖**（2026-08-21 修复：原为无条件 upsert 覆盖，导致容器重启会把管理员手动调的积分重置回默认值）。

entrypoint 启动即 `python seed_reward.py`，保证积分/转盘/直兑配置存在（幂等：已存在不覆盖）。

> Python 实操初阶积分下调为 `100→2 / 90→1 / <90→0`（防小朋友刷积分）；tier 倍率（进阶×2、挑战×3）仍生效。
