> 关联：[题型与出题规范](题型与出题规范.md)、[积分与奖励体系](积分与奖励体系.md)

## 1. 组卷（POST /api/exam/start）

入口在 **home.html**（非 quiz.html）：选科目→章节/题型/题数/模式，结果写 `localStorage['quiz_exam']` 后跳 `quiz.html`。

- 题数白名单：**`(1, 10, 20, 30, 40, 50)`**（1 题档仅 Python 实操单题），否则 400「题目数量只能选择 1、10、20、30、40、50 题」。前端档位 chip 为 10/20/30/40/50，默认 文化类=50 / 编程理论=10（`home.html`）。
- **自动降档**（2026-08-24 积分档位化改造）：题池数量不足所选档位时，自动降到「不超过题池数量的最大档位」（如选 50 题但池内 49 题 → 降为 40 题档，不凑 49）。响应带 `downgraded` 标记，前端提醒学员「题目数不够，已降至 xx 题档位」。目的：堵死「虚选高档位拿高积分」漏洞。
- 不落库、未交卷不产生空记录（`exam.py:316`）。
- 排除弃用题：`deprecated IS NULL OR = False`（`exam.py:319`）。
- `mode=wrong` 走错题池（未 mastered），同样受科目 `allowed_types` 约束（`exam.py:329-330`）。
- 题型过滤：请求 `types` ∩ 科目 `allowed_types`，交集空返回空题目（`exam.py:337-340`）。
- **4 层优先抽题**（`_rank_pool`，normal 模式），语义上 4 层优先级，代码用 2 层实现：
  - **层1 未答过的题** → 优先抽取，层内 `random.shuffle` 随机序；
  - **层2 答过且出错较多的题** → 排序键第一项 `-wrong_count`（错次降序）；
  - **层3 答过且出错较少 / 无错的题** → 排序键第二项 `+attempt_count`（做题少的排前）；
  - **层4 随机兜底** → 排序前先 `shuffle` 再稳定 sort，并列项保持随机序（错次都为 0 的题之间随机）。
  - 实现：`layer1`（未答过）+ `layer2`（所有答过的，复合排序键），`selected = (layer1 + layer2)[:count]`。一次考试内不重复。目的：让掌握度「覆盖度 80%」门槛可公平达成（而非赌随机运气）。`wrong` 模式保留纯随机（`random.shuffle(pool)`）。
- **防泄题**：reading 子题剥离 answer/explanation（`exam.py:359-363`）；code 题下发 explanation 但 `answer` 置 None（`exam.py:301-302`）。

## 3. 交卷（POST /api/exam/submit）

入参 `{subject_id, mode, topic_ids, answers:[{question_id,user_answer}], duration_seconds}`（`exam.py:434-500`）。
- 校验 answers 非空 + question_id 全部存在（否则 400）。
- `started_at = now - duration_seconds`（`exam.py:449`，时长从前端上报还原）。
- 逐题 `_judge` 判分，写 `AnswerRecord`（is_correct / llm_score / llm_stars / llm_feedback / run_output）。
- 总分 `score = int(correct / total * 100)`（`exam.py:493`）。
- 错题入本：答错且 `ar_score < 60` → upsert `wrong_questions`（wrong_count++）。
- **掌握度增量 upsert**：判分后对本次涉及 (topic, tier) 调 `compute_mastery_for_topics` 重算并 `upsert_student_mastery`（在 `points_earned` 之后、`db.commit()` 之前，同事务）。
- **精通奖励钩子**（2026-08-24）：upsert 前后状态对比检测「非精通→精通」跃迁；有新精通则发放转盘等额积分（动态 `wheel_cost`）+ 一次性补发历史未发奖精通课，同事务写 `mastery_rewards`。返回 `ExamRecordOut.mastery_rewards`，前端弹烟花弹窗。详见 [积分与奖励体系](积分与奖励体系.md) §4.5。
- 返回 `ExamRecordOut`（含 `points_earned`）。
- 历史积分从 `points_ledger` 回填（`exam.py:521-526`）。

> ⚠️ 已知落差：`submit_exam` 未传入 `data.mode`（错题重做也落成 `custom`）；`topic_ids` 未持久化；`AnswerRecord.time_used` 恒为 0。

## 4. 积分发放 `_award_exam_points`（`exam.py`）

与成绩**同一事务** `db.commit()`：
0. **掌握度闸门**（最前）：查 `student_mastery` 表，本次涉及的课（按 `record.tier`）**全部 mastered** → 直接 `return 0`（不发分，防刷分）。任一未 mastered → 继续正常发分。
1. **查表（2026-08-24 档位化后，一套机制）**：在 `scoring_rules` 中，先按科目专属（`subject_id == record.subject_id`）→ 再按全局（`subject_id IS NULL`）；各自内部先精确匹配 `question_count == record.total`（本次实际题数），缺则回落 `question_count = 0`；`score_band <= record.score AND is_active` 取 `score_band` 最大者。
2. 无命中 = 0；`pts<=0` 直接 return 0，不写流水（**不再有 <80 硬编码**，如 50 题档 60 分也有 1 积分）。
3. 写 `PointsLedger(reason="exam_reward", ref_id=record.id, balance_after=...)`。

积分矩阵：题数档位 10/20/30/40/50 × 分数段（见 [积分与奖励体系](积分与奖励体系.md) §5）；Python基础实操为科目专属规则（1 题档，100→2 / 90→1）。
> 掌握度闸门无开关、对所有科目无条件生效（判定基准固定「精通」，tier 独立：初阶精通不挡进阶拿分）。详见 [掌握度与学情联动](掌握度与学情联动设计.md)。

## 5. 记录查询

- `GET /api/exam/records`（列表，不含明细）
- `GET /api/exam/records/{id}`（含每题明细）
- `GET /api/wrong-questions`、`POST /api/wrong-questions/{id}/master`、`DELETE /api/wrong-questions/{id}`（错题本标掌握/删除）

前端：`records.html`（学员记录+明细）、`wrong.html`（错题本）。
