# 掌握度与学情联动 设计方案

> 状态：设计文档 v2（2026-08-21，掌握度系统重构：持久化表 + 三硬门槛算法 + 积分闸门 + 组卷4层优先；已双端部署 本地 + ECS `106.14.99.100`）
> 目标：把「课掌握度」和「薄弱知识点 / 反复错题榜 / 低正确率题目 / 学情分析 / 积分发放」打通，使多套数据**口径一致、互相联动、永不矛盾**，并让掌握度成为**积分发放的闸门**。
> 范围：掌握度模块（mastery）+ 组卷/积分（exam）+ 学情分析（analytics）。新增 `student_mastery` 持久化表，不改动 `questions` / `answer_records` 既有表结构。

---

## 1. 设计背景与痛点

此前存在两套互相矛盾的口径：

- **掌握度**（`mastery`）：按学员 × 课、取**最近 3 次练习窗口**算"通过/精通"，看的是*当前掌握状态*。
- **薄弱知识点 TOP10**（`analytics_weakness`）：按**全班历史答题正确率最低**排名，全时段、跨所有学员聚合。

于是出现诡异现象：「掌握度里某课已通过，薄弱榜里它还在」。根因是**两者对"课"的判定口径不一致**。

此外，历史诉求「课程掌握度达标的就不再给积分（防刷分）」一直停留在需求层，未接进积分发放代码——本次一并落地。

系统只有两个小学员（瑶瑶 #2、诺诺 #4），不存在"班级"聚合概念，所有视图都应**落实到人**。

---

## 2. 设计原则

1. **持久化 + 统一算法，从数据层消灭矛盾**：掌握度结果落 `student_mastery` 表（submit 后增量 upsert），薄弱分析、掌握度看板、积分闸门全部**读表**，物理上不可能"通过却还进薄弱榜"或口径漂移。
2. **落实到人**：所有分析视图以"学员"为维度；管理端掌握度页面是**学员 × 课程（× 档位）的矩阵**，不做班级汇总。
3. **积分闸门**：某次考试涉及的课全部达「精通」，则该次不再发放积分（防刷分）。判定基准固定「精通 mastered」，tier 独立（初阶精通不挡进阶）。
4. **组卷配套**：抽题按「未答过优先」分层，使覆盖度门槛可公平达成（详见 [组卷与答题流程](组卷与答题流程.md)）。
5. **向后兼容**：`analytics_weakness` 不传 `student_id` 时仍返回原"全体历史汇总"口径。

## 3. 掌握度模型（mastery）

文件：`core/mastery.py`（算法层）+ `models.py`（`StudentMastery` 表）+ `routers/mastery.py`（路由）

### 3.1 持久化表 `student_mastery`

| 列 | 类型 | 说明 |
|---|---|---|
| student_id / subject_id / topic_id / tier | Integer | 作用域「学员 × 科目 × 课 × 档位」，联合唯一 (student_id, topic_id, tier) |
| status | String | 掌握状态（mastered / passed / practicing / not_started） |
| rate | Float | 累计正确率（0-100） |
| coverage | Float | 覆盖度（不重复题/课总题，0-100） |
| answered_count | Integer | 累计答题次数 N（含重复题重做） |
| distinct_count | Integer | 答过的不重复题数 D |
| correct_count | Integer | 累计答对数 C |
| topic_total | Integer | 该课该档题库总量 Q |
| updated_at | DateTime | 最后更新时间 |

- 更新时机：`submit_exam` 判分后，对该次涉及的 (topic, tier) 重算并 **upsert**（有则更新、无则插入），非实时全算。
- 建表：`models.py` 的 `Base.metadata.create_all` 自动建表；老库由回填脚本 `scripts/mastery_backfill.py` 建表 + 一次性全量回填（幂等，清空后重算）。

### 3.2 核心指标

| 指标 | 含义 | 计算 |
|---|---|---|
| `rate` (R) | 累计正确率 | 累计正确数 C / 累计答题次数 N |
| `coverage` (Ccov) | 覆盖度 | 不重复题数 D / 该课该档题库总量 Q |
| `answered_count` (N) | 做题数 | 累计答题次数（重复题重做也计） |
| `distinct_count` (D) | 不重复题数 | 答过的去重题数 |

### 3.3 状态判定（累计统计 + 三硬门槛，去场次）

| 状态 | 英文 | 判定条件 |
|---|---|---|
| 精通 | `mastered` | N ≥ max(Q×0.8, 10) 且 R ≥ 90% 且 Ccov ≥ 80% |
| 通过 | `passed` | N ≥ max(Q×0.5, 8) 且 R ≥ 85% 且 Ccov ≥ 50% |
| 练习中 | `practicing` | 有答题但未达通过 |
| 未开始 | `not_started` | 无任何答题 |

> 科学依据：Bloom 掌握学习（正确率 85–90%）+ Popham 标准参照测验（样本量 ≥10–15 题）。
> 关键：**去掉「最近 N 次窗口 / 场次」维度**，改为纯累计统计 + 三硬门槛——做题数下限 `max(Q×0.8, 10)` 防止"题少时刷几次就精通"，覆盖度 80% 防止"只刷几道简单题反复刷"。
> `review`（需复习）标签保留在 `STATUS_LABEL` 中，但当前算法暂不产出（历史曾通过但重做错题回落的情况暂归 `practicing`），留待后续按表更新历史判定。

### 3.4 组卷配套：4 层优先抽题

为让覆盖度门槛可公平达成（而非赌随机运气），`exam.py` 的 normal 模式抽题改为 4 层优先：

```
层1 未答过的题        → 随机洗牌，置最前
层2 答过且有错的题     → 按错次降序（错多排前）
层3 答过但没错/错少的题 → 按做题次数升序（做得少排前）
层4 兜底              → 剩余随机
selected = (层1+层2+层3+层4)[:count]
```

- 一次考试内不重复（各层互斥）；`count > pool` 时返回全部可用题。
- `wrong`（错题重做）模式不受影响，保留原逻辑。
- 详见 [组卷与答题流程](组卷与答题流程.md)。

## 4. 接口清单

### 4.1 掌握度

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/mastery/me?student_id=` | 学员看自己；家长看已绑定孩子；管理员可带 `student_id`。**读 `student_mastery` 表**（无记录 = not_started） | student/parent/admin |
| GET | `/api/admin/mastery?tier=&subject_ids=` | **学员 × 课程（× 档位）矩阵**：`subject_ids` 逗号分隔多科目（空=全部）；响应 `subjects[]` + `topics[]`（每条带 `subject_name` + `cells`={student_id:{tier:{status,status_label,rate,coverage}}} + `counts`/`pass_rate`/`mastery_rate`）。**读表** | admin |

### 4.2 学情分析（联动改造）

| 方法 | 路径 | 改造点 |
|---|---|---|
| GET | `/api/admin/analytics/weakness?student_id=` | 新增 `student_id`：传学员时，薄弱知识点**只列该学员"练习中/需复习"的课**（已通过/精通/未开始一律排除）；反复错题榜、低正确率题目每条带 `topic_id` + 该学员此课掌握状态（已掌握标"已掌握·偶发错"）。不传则原口径。 |
| GET | `/api/admin/analytics/student/{id}` | `by_topic` / `top_wrong` 补 `topic_id` + 掌握状态徽章；`score_trend` 供掌握度全景成绩趋势图 |
| GET | `/api/admin/analytics/recent-activity?student_id=&subject_ids=&days=&limit=` | **最近刷题动态**（近 N 天场次明细 + 各课答题量聚合），过滤条件下沉 SQL 层。见 [管理后台与学情分析](管理后台与学情分析.md) |

### 4.3 复用辅助（`core/mastery.py`）

- `eval_topic_tier(stats, totals, student_id, topic_id, tier)`：单点判定（被算法层复用）。
- `compute_mastery_for_topics(db, student_id, topic_tier_pairs)`：批量计算，供 submit 增量 upsert 与回填脚本共用。
- `upsert_student_mastery(db, student_id, computed_rows)`：upsert 进 `student_mastery` 表。
- `routers/analytics.py` 的 `_student_mastery_map` / `routers/mastery.py` 的 `_build_student_mastery` 均改**读 `student_mastery` 表**，不再实时全算。

> 注意（踩坑）：SQLite 不支持 `func.case(...).else_()`，须用 `sqlalchemy.case`。

## 6. 联动流程

```
薄弱分析（选某学员）
  ├─ 薄弱知识点：只列 练习中/需复习 的课
  ├─ 反复错题榜 / 低正确率题：每条带"所属课掌握状态"，已掌握标"偶发错"
  └─ 点任意课 → 掌握度详情

掌握度全景（选科目/档位/学员）
  ├─ 柱状图：每课覆盖度%（精通度）
  ├─ 矩阵表：每课 × 每位学员的掌握状态 + 覆盖度
  └─ 选单学员时：下方显示「成绩趋势」折线图

积分发放（submit_exam）
  └─ 涉及课全部 mastered → 不发分；任一未 mastered → 正常发分
```
