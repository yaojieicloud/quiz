# 掌握度与学情联动 设计方案

> 状态：设计文档 v1（2026-08-12，已双端部署：本地 `quiz-local` + ECS `106.14.99.100`）
> 目标：把「课掌握度」和「薄弱知识点 / 反复错题榜 / 低正确率题目 / 学员档案」打通，使两套数据**口径一致、互相联动、永不矛盾**。
> 范围：学习分析模块（mastery + analytics），不改动 `questions` / `answer_records` 既有表结构。

---

## 1. 设计背景与痛点

此前存在两套互相矛盾的口径：

- **掌握度**（`mastery`）：按学员 × 课、取**最近 3 次练习窗口**算"通过/精通"，看的是*当前掌握状态*。
- **薄弱知识点 TOP10**（`analytics_weakness`）：按**全班历史答题正确率最低**排名，全时段、跨所有学员聚合。

于是出现诡异现象：「掌握度里某课已通过，薄弱榜里它还在」。根因是**两者对"课"的判定口径不一致**。

另外系统只有两个小学员（瑶瑶 #2、诺诺 #4），不存在"班级"聚合概念，所有视图都应**落实到人**。

---

## 2. 设计原则

1. **统一算法，从数据层消灭矛盾**：薄弱分析、学员档案、掌握度看板，全部复用 `mastery._eval_topic` 这一套状态判定，物理上不可能"通过却还进薄弱榜"。
2. **落实到人**：所有分析视图以"学员"为维度；管理端掌握度页面是**学员 × 课程的矩阵**，不再做班级汇总。
3. **双向联动（可跳转）**：薄弱榜里的课点一下 → 打开该学员掌握度详情；掌握度里正位于薄弱榜的课打角标 → 点角标跳回薄弱分析。
4. **向后兼容**：`analytics_weakness` 不传 `student_id` 时仍返回原"全体历史汇总"口径（仅给每条补 `topic_id` 便于联动）。

---

## 3. 掌握度模型（mastery）

文件：`src/routers/mastery.py`

### 3.1 判定维度

- 维度：**学员 × 科目 × 课（topic）**。
- 数据来源：`answer_records`（通过 `exam_records` 关联学员、题目关联 `topic_id`）。
- 练习序列：取该学员该课**最近 N 次（默认 3 次）练习**作为"近期窗口"。
- 题量口径：`topic_total` = 该课题目总数（覆盖度分母）。

### 3.2 核心指标

| 指标 | 含义 | 计算 |
|---|---|---|
| `rate` (R) | 近期正确率 | 近期窗口内 `correct / total` |
| `coverage` (C) | 覆盖度 | 近期窗口作答题数 / 该课题目总数（百分比） |
| `sessions` | 练习次数 | 近期窗口内的练习次数 |
| `total` / `correct` | 窗口内总题数 / 正确数 | — |

### 3.3 状态判定（阈值）

| 状态 | 英文 | 判定条件 |
|---|---|---|
| 精通 | `mastered` | R ≥ 95% 且 C ≥ 80% |
| 通过 | `passed` | R ≥ 90% 且 C ≥ 50% 且样本足够（窗口≥3次且最近3次≥85%） |
| 需复习 | `review` | 曾达标，但近期窗口 R < 70% |
| 练习中 | `practicing` | 开始练习但未达通过 |
| 未开始 | `not_started` | 无作答记录 |

> 关键门槛（避免"只练1题全对就判通过"）：必须通过/精通要求覆盖度与样本门槛；`practicing` 阶段即使 R=100% 但 C 过低也不算通过。

## 4. 接口清单

### 4.1 掌握度

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/mastery/me?student_id=` | 学员看自己；家长看已绑定孩子；**管理员须带 `student_id`** | student/parent/admin |
| GET | `/api/admin/mastery/student/{id}` | 管理员查看单学员掌握度（供深链） | admin |
| GET | `/api/admin/mastery?subject_id=` | **学员 × 课程矩阵**：响应含 `students:[{id,name}]` + `topics[].cells`={student_id:{status,status_label,rate,coverage}} | admin |

### 4.2 学情分析（联动改造）

| 方法 | 路径 | 改造点 |
|---|---|---|
| GET | `/api/admin/analytics/weakness?student_id=` | 新增 `student_id`：传学员时，薄弱知识点**只列该学员"练习中/需复习"的课**（已通过/精通/未开始一律排除）；反复错题榜、低正确率题目每条带 `topic_id` + 该学员此课掌握状态（已掌握标"已掌握·偶发错"）。不传则原口径。 |
| GET | `/api/admin/analytics/student/{id}` | `by_topic` / `top_wrong` 补 `topic_id` + 掌握状态徽章 |

### 4.3 复用辅助

- `mastery._eval_topic(sessions, topic_total)`：状态判定核心，被上述所有接口共用。
- `admin._student_mastery_map(db, student_id)`：复用 `_load_student_rows / _rows_to_sessions / _eval_topic` 产出"课 → 状态"字典，供薄弱分析/学员档案调用。

> 注意（踩坑）：SQLite 不支持 `func.case(...).else_()`，须用 `sqlalchemy.case`。

## 5. 前端清单

| 文件 | 角色 | 联动要点 |
|---|---|---|
| `src/static/mastery.html` + `js/mastery.js` | 学员端掌握度看板 | 支持 `?student_id`（管理员深链）+ `?topic` 高亮滚动；对正位于薄弱榜的课打"⚠ 在薄弱榜"角标（**双向联动**） |
| `src/static/admin-mastery.html` + `js/admin-mastery.js` | 管理端学员掌握度 | 标题"学员掌握度"；**矩阵表**：行=课程，列=每位学员，单元格=该学员此课状态色块；点格子 → `mastery.html?student_id=&topic=` 新标签 |
| `src/static/admin.html` | 管理后台 | 薄弱分析 tab 加"学员"下拉；三张表（薄弱知识点/反复错题/低正确率）带掌握状态徽章，点课 → 学员掌握度详情；学员档案高频错题/薄弱知识点带状态徽章 |

状态色板：通过=绿、精通=橙、需复习=红、练习中=蓝、未开始=灰。

## 6. 联动流程

```
薄弱分析（选某学员）
  ├─ 薄弱知识点：只列 练习中/需复习 的课
  ├─ 反复错题榜 / 低正确率题：每条带"所属课掌握状态"，已掌握标"偶发错"
  └─ 点任意课 → mastery.html?student_id=&topic=  （跳学员详情）

mastery.html（学员详情）
  └─ 正位于薄弱榜的课程 → "⚠ 在薄弱榜"角标 → 点角标跳回薄弱分析
```

交叉校验结论：学员#4 有 3 个已通过/精通的课，**全部不进薄弱榜，矛盾项 = []**。
