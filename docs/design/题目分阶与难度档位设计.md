# 题目分阶与难度档位设计

> 关联任务清单：[题目分阶_任务清单](../plan/题目分阶_任务清单.md)
> 关联：掌握度算法（`core/mastery.py`）、学情分析（`routers/analytics.py`）、组卷与积分（`routers/exam.py`）

## 1. 背景与目标

当前 `questions.difficulty`(1/2/3) 是**题内微难度**，仅作存储、不参与组卷与积分；全部题目在用户认知里都属于「初级」。

目标：引入更高一层的**分阶档位（tier）**维度，将题目划分为：

- `1 = 初级`（存量题目全量归入）
- `2 = 进阶`（后续新增）
- `3 = 挑战`（后续新增）

并让**组卷抽题、错题重做、积分倍率、掌握度、学情分析、历史记录展示**全链路按 tier 联动。难度选择为**单选**（多选一）。

决策（已确认）：
- **A** 现有题库全部关联到初级（迁移一次性回填 `tier=1`）。
- **B** 掌握度 / 学情等所有相关功能都要做 tier 化（逐项见任务清单）。
- **C** 组卷选了某档位但无对应题目时，提示「没有符合条件的题目」。

## 2. 概念澄清：tier ≠ difficulty

| 维度 | 字段 | 含义 | 是否参与逻辑 |
|---|---|---|---|
| 分阶档位 | `questions.tier`(新增) | 初级/进阶/挑战，课程层级 | 是：组卷抽题、积分倍率、掌握度、学情 |
| 题内微难度 | `questions.difficulty`(已有) | 1简单/2中等/3较难，题内细粒度 | 否（保留为元信息，未来可用于题内排序） |

两个维度正交：同一档位内仍可含不同微难度的题。v1 不改动 `difficulty` 语义。

## 3. 数据模型

### 3.1 `questions.tier`（新增列）
```python
tier = Column(Integer, default=1, index=True)  # 1初级 2进阶 3挑战
```
- 存量题目迁移回填为 `1`。
- 组卷抽题按 `tier` 过滤；同一 exam 内题目档位一致（前端单选决定）。

### 3.2 `exam_records.tier`（新增列）
```python
tier = Column(Integer, default=1)  # 本次答题所选档位，落库便于历史展示与后续按档统计
```
- 提交时写入用户所选档位；积分倍率据此计算。

### 3.3 `tier_config`（新增配置表）
| 列 | 类型 | 说明 |
|---|---|---|
| `tier` | Integer PK | 1/2/3 |
| `name` | String | 初级/进阶/挑战 |
| `points_multiplier` | Integer | 积分倍率，初阶=1、进阶=2、挑战=3 |

- 倍率走表（非硬编码），对应「暂设」诉求：调倍率/加挑战档只改数据。
- 种子数据：`(1,'初级',1) (2,'进阶',2) (3,'挑战',3)`。

### 3.4 常量层 `core/tier.py`
集中定义枚举与读取函数，避免散落硬编码：
- `TIER_PRIMARY=1 / TIER_ADVANCED=2 / TIER_CHALLENGE=3`
- `TIER_NAMES = {1:'初级',2:'进阶',3:'挑战'}`
- `ACTIVE_TIERS = [1,2,3]`
- `get_tier_multiplier(db, tier) -> int`：读 `tier_config`，缺省回退常量。
- `tier_label(tier) -> str`

## 4. 组卷与积分联动

### 4.1 抽题（`routers/exam.py:start_exam`）
- 三模式（custom / wrong / random）统一加过滤：`Question.tier == data.tier`。
- **错题重做（wrong 模式）**：错题本 `WrongQuestion` 关联 `Question`，按所选 tier 过滤错题；若该档位无错题 → 池为空 → 前端提示「没有符合条件的题目」。
- 向后兼容：`ExamStartRequest.tier` 默认 `1`，旧调用/未传时仍抽初级。

### 4.2 积分倍率（`routers/exam.py:_award_exam_points`）
- 现有逻辑：先查 `SubjectPoints` 覆盖或全局 `ScoringRule`（得分档 100→5 / 90→4 / 80→3 / <80→0）。
- 改造：`pts = 基础分 × tier_config.points_multiplier`。
- `submit_exam` 将用户所选 `tier` 写入 `ExamRecord.tier` 后再算分。
- 进阶（倍率2）满分示例：100分 → 5×2 = 10 分。

### 4.3 题目增改（`routers/questions.py`）
- `create_question` / `batch_import` 写入 `tier`（默认 1，import 脚本可显式指定）。

## 5. 掌握度 tier 化（`core/mastery.py` + `routers/mastery.py`）

掌握度算法以「学员 × 课」为作用域；tier 化后作用域升级为「学员 × 课 × 档位」。

### 5.1 算法层改造（`core/mastery.py`，2026-08-21 已重构为「累计统计 + 三硬门槛」）

作用域「学员 × 课 × 档位」不变；算法由「最近 N 次窗口 / 场次」重构为**纯累计统计**：

- 做题数 N = 累计答题次数（含重复题重做）；不重复题 D；正确数 C；正确率 R = C/N；覆盖度 Ccov = D/Q。
- 判定（去场次）：`mastered = N≥max(Q×0.8,10) 且 R≥90% 且 Ccov≥80%`；`passed = N≥max(Q×0.5,8) 且 R≥85% 且 Ccov≥50%`；其余 practicing / not_started。
- 关键函数：`_topic_totals(db)` 按 `(topic_id, tier)` 统计活跃题数；`_load_student_rows` 返回 `Question.tier`；`_rows_to_stats` 按 `(uid, topic_id, tier)` 累计；`eval_topic_tier(...)` 单点判定；`compute_mastery_for_topics(...)` 批量计算；`upsert_student_mastery(...)` upsert 进 `student_mastery` 表。

> 科学依据：Bloom 掌握学习 + Popham 标准参照测验。`max(Q×0.8, 10)` 下限防"题少刷几次就精通"，覆盖度 80% 防"只刷几道简单题反复刷"。

### 5.2 持久化与路由输出（`models.py` + `routers/mastery.py`）

- 新增 `student_mastery` 表（`(student_id, topic_id, tier)` 联合唯一），submit 后增量 upsert，不再实时全算。
- `_build_student_mastery`：读 `student_mastery` 表，每个 topic 返回 `tiers: {1:{status,status_label,rate,coverage,...}, 2:{...}, 3:{...}}`（无记录 = not_started）。
- `class_mastery`（学员×课程矩阵，`/api/admin/mastery`）：读表；`cells` 为 `{student_id: {tier: {...}}}`；支持 `subject_ids` 逗号分隔多科目（空=全部）；`counts`/`pass_rate`/`mastery_rate` 按所选 tier 聚合。
- 掌握度、学情、积分闸门复用同一 `core/mastery` + 同一张表，口径一致。

> 设计要点：初级做对**不**自动升级进阶掌握度，二者独立——tier 化天然满足。

## 6. 学情分析 tier 化（`routers/analytics.py`）

- `_student_mastery_map(db, student_id, tier=None)`：key 由 `topic_id` 改为 `(topic_id, tier)`；tier 给定时仅算该档掌握度映射。
- `analytics_weakness`（薄弱TOP10 / 反复错题榜 / 低正确率题目）：
  - 新增 `tier` 查询参数；给定时，`WrongQuestion`/`AnswerRecord` 关联 `Question.tier` 过滤，且薄弱判定用该档掌握度；
  - 不给定时返回全部档位（前端可加档位筛选）。
- `analytics_overview` / `analytics_student`：涉及掌握度/薄弱处同步带 tier 维度；overview 可加「各档位薄弱数」统计。
- AI 周报（`analytics_report`）：若引用薄弱点，按所选 tier 取数（报告生成时可带 `tier` 参数）。

## 8. 迁移与数据回填

- 迁移文件 `src/migrations/0003_tier.py`：
  1. `CREATE TABLE tier_config` + 种子三档；
  2. `add_column(questions, tier, INTEGER, default=1)` —— SQLite 给存量行填 1（全量初级）；
  3. `add_column(exam_records, tier, INTEGER, default=1)`。
- 幂等（`add_column`/`table_exists` 已具备），可重复执行、跨本地/ECS 重放。
- 不走删库、不手写散落 ALTER。

## 9. 验收标准

1. 迁移执行后：`schema_migrations` 含 `0003_tier`；`questions.tier` 全为 1；`tier_config` 三行；`exam_records` 新增列。
2. 组卷选「进阶」抽到的题 `tier` 全为 2；选「初级」同前；选某档无题时前端提示空。
3. 进阶满分积分 = 初阶 ×2（验证 `points_ledger.delta`）。
4. 掌握度接口按 tier 返回独立状态；初级掌握不影响进阶状态。
5. 学情薄弱 TOP10 按 tier 过滤生效。
6. 本地 docker 容器全链路验证通过；ECS 按 docker build 流程部署后验证通过。
