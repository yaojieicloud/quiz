# 系统架构总览

> 定位：让维护者（含 AI）一眼看懂整体结构——技术栈、模块划分、请求流向、数据模型、目录布局。
> 各模块细节见 `docs/design/` 下的分册；部署与运维见 [部署与运维](部署与运维.md)。

---

## 1. 技术栈

- **后端**：FastAPI + SQLAlchemy 2.x（ORM）+ SQLite（单文件数据库）
- **鉴权**：JWT Bearer（`python-jose` + `passlib` pbkdf2_sha256），`require_role` 依赖工厂做角色网关
- **前端**：原生多页 HTML + 原生 JS（`fetch` 直连 API），无构建步骤；`common.js` 提供公共能力
- **图表**：ECharts 5.5（CDN，加载失败降级）
- **AI 能力**：OpenAI 兼容 SDK 调大模型（aliyun 主 / deepseek 兜底），沙箱实跑代码
- **部署**：Docker（镜像 `quiz-system`），本地 `quiz-local`、ECS `quiz-system` 双环境，数据卷持久化

## 2. 角色与权限

| 角色 | 用途 | 关键能力 |
|---|---|---|
| `student` | 学员（小朋友） | 刷题、看错题本/掌握度/积分/抽奖/直兑 |
| `parent` | 家长 | 绑定孩子（bind_code）、查看孩子记录/掌握度 |
| `admin` | 管理员 | 全部管理接口（科目/题目/学情/奖励/运维） |

JWT payload 含 `sub`（用户 id）；`get_current_user` **只用 sub 查库，role 取自 DB**（改角色即时生效）。注册需 `regkey`（默认 `openschool2026`），当前未开放自由注册。

## 4. 请求流向

```
浏览器 → /static/*.html（原生页面）
       → fetch /api/...  →  FastAPI router
                            → Depends(get_current_user) 校验 JWT
                            → Depends(require_role(...)) 校验角色
                            → 业务函数（ORM 读写 SQLite）
                            → Pydantic schema 序列化返回
```

核心依赖（`core/deps.py`）：
- `get_current_user`：解析 Bearer token → 查 `users` → 返回 User 对象（失败 401）
- `require_role(*roles)`：工厂，校验 `user.role in roles`（否则 403）

## 5. 数据模型（核心表）

| 表 | 作用 | 关键关系 |
|---|---|---|
| `users` | 账号（含 role / bind_code） | 1—N `parent_child` |
| `parent_child` | 家长—孩子绑定 | FK → users（parent_id / child_id） |
| `subjects` | 科目（grade / category / allowed_types） | 1—N `topics` / `questions` |
| `topics` | 课（unit + name 两级，或编程类扁平） | N—1 `subjects`；N—1 `questions` |
| `questions` | 题目（9 种题型 / 难度 / 容差 / expected_output / tier 档位） | N—1 `subjects`/`topics` |
| `exam_records` | 一次答题（总分/正确数/时长/模式/tier） | 1—N `answer_records`；1—N `points_ledger` |
| `answer_records` | 每题作答（user_answer / is_correct / llm_score / llm_stars） | N—1 `exam_records`/`questions` |
| `wrong_questions` | 错题本（wrong_count / mastered） | 唯一 (user_id, question_id) |
| `student_mastery` | 掌握度持久化（学员×课×档位的 status/rate/coverage/答题统计） | 唯一 (student_id, topic_id, tier)；submit 后增量 upsert |
| `points_ledger` | 积分流水（delta / reason / balance_after） | N—1 `users` |
| `scoring_rules` / `subject_points` | 积分矩阵 / 科目积分覆盖 | — |
| `redeem_items` / `wheel_prizes` / `plays` / `direct_redemptions` | 直兑 / 转盘 / 抽奖记录 | — |
| `ai_reports` / `llm_calls` | AI 周报 / LLM 调用审计 | — |

> 迁移机制：`main.py` 启动 `Base.metadata.create_all`（首次建全表）+ `run_migrations()`（为老库补齐增量字段）。新增字段走 `src/migrations/` 迁移文件，禁止手写散落 `ALTER`。见 [数据库迁移机制](数据库迁移机制.md)。

## 6. 目录布局

```
quiz/
├── README.md                 # 项目总入口（架构/功能/部署/运维索引）
├── docs/
│   ├── design/               # 各功能设计文档（本目录）
│   └── plan/                 # 方案/规划类提案（积分方案、实时出题改造、未来规划）
├── src/
│   ├── main.py               # 应用入口、路由挂载、静态目录
│   ├── models.py             # 全部 ORM 模型
│   ├── schemas.py            # Pydantic 请求/响应模型
│   ├── config.py             # 配置与环境变量
│   ├── database.py           # 引擎 / Session
│   ├── core/                 # security / deps / llm_client / llm_grader / code_runner
│   ├── routers/              # 各业务路由
│   ├── static/               # 前端页面 + js + css
│   ├── data/                 # 题库 JSON + 导入/迁移脚本
│   ├── seed_reward.py        # 积分/转盘/直兑种子（幂等）
│   ├── fetch_db.py           # 拉线上库到本地
│   └── Dockerfile / entrypoint.sh / docker-compose.yml
└── quiz-data/ (本地，不进 git)  # 数据库 + 密钥 + 备份
```
