# 习题人工复核规范

> 版本：v2.0（2026-08-27 重构，取代 v1.0 的 Python 理论单科版）
> 适用范围：全科目 —— 语文 / 数学 / 英语 / Python基础理论 / Python基础实操（含后续新增科目）
> 定位：题目面向学员开放前的**人工质量守门**。与 `python-theory-check-plan.md`（自动化结构核对 PASS/FIX/DROP）互补：自动核对管"结构完不完整"，本规范管"内容对不对、该不该给孩子做"。

## 一、什么时候复核

- 新录入 / 批量导入的题目，开放给学员前必须逐题过本规范
- 历史批次未复核的，按课程（topic）为单位分批补审

## 二、复核检查点（5 项，逐题过）

### 检查点 1：题目正确性（全题型通用）

- 题干通顺、符合常理、无歧义、不缺条件
- **答案正确**（答案本身错的必须修）
- 选项正确合理：无重复选项、无恒对/恒错项、干扰项合理不误导

### 检查点 2：连线题专项（type=match）

- 左列（`options`）内容正确合理；右列（`match_options`）内容正确合理
- 左右一一对应、无歧义（一个左项只能对一个右项）
- ~~右列顺序必须乱序~~：前端答题界面已自动 Fisher-Yates 随机乱序右列（quiz.html），`data-idx` 保持原始索引，判分逻辑不受影响。数据库中的顺序不影响答题公平性，无需复核。

### 检查点 3：判断题专项（type=judge）

- 陈述本身事实正确、无歧义（不能有两种理解）
- 答案（对/错）与陈述一致

### 检查点 4：课程范围（全科目 —— 超纲判定①）

- 题目知识点与所属课程（topic）对比：**本课程没教的内容 = 超纲**
- 语文 / 数学 / 英语：紧跟课本年级走（出题铁律：语文部编版、数学人教版、英语人教 PEP 2024 秋季改版），单元/课时/词汇表以教材为准，不跨年级、不超前
- Python 两科：只用当前章节教过的知识点，后文章节内容禁止提前出现（串课=超纲）

### 检查点 5：认知范围（主要针对 Python 两科 —— 超纲判定②）

- 唯一自测句：**「一个没学过这些概念的 9 岁孩子，能不能凭已学知识做对？」**
- 不能 / 模棱两可 → 废弃。参照物是小学生，不是程序员
- 语文/数学/英语若涉及生活常识，同样以小学生认知为准

### 检查点 6：Python 基础实操复核深度（2026-08-27 新增）

Python 基础实操复核**不需要每题都亲手实跑一遍参考代码**，满足以下三点即通过：

1. **语义正确**：题干通顺、要求明确、与参考代码逻辑一致
2. **知识认知符合范围**：所用知识点在该课（或挪课后目标课）教学范围内，认知匹配小学生
3. **题目编程可做**：参考代码逻辑上能跑通、有确定输出即可

仅当存在以下情形时才必须实跑验证：参考代码输出可能不稳定（含计时/随机/集合无序迭代）、怀疑逻辑错误、或修复后需重算 `expected_output`。

## 三、处置规则

| 结论 | 判定 | 处置 |
|------|------|------|
| ✅ 保留 | 5 项全过 | 不动 |
| 🔧 修复（FIX） | 答案错 / 选项错或不合理 / 题干歧义 / 答案映射错误 | 改题（管理端编辑或 `PUT /api/questions/{id}`），改后重审；**修复不是废弃** |
| ❌ 废弃（deprecated=1） | 超课程范围 / 超认知范围 | 标记废弃，不物理删除（学习记录/统计仍引用） |

> 铁律：**宁可少几道题，不可上一道超纲题。** 存疑即废弃，不纠结。
> 分清边界：答案错 → 修；内容超纲 → 废。不要把"答案错"当超纲废掉。

## 四、Python 认知红线速查（检查点 5 细则，任一踩线即废弃）

| 类别 | 超纲点举例 |
|------|-----------|
| 串课 | 字符串方法/列表/字典/函数/三元表达式/elif 混入前置课 |
| 底层机制 | `is` 同一性、`True+1`、短路求值、`id()/dir()`、报错类型名 |
| 超纲数学/类型 | 复数、进制、科学计数、浮点误差、步长切片、字典序比较、`round` 舍入、`r''` |
| 工程概念 | 文件/日志、`import`、异常处理、type hint、生成器表达式 |

**正材清单（防误杀，这些保留）**：变量盒子比喻、`print` 的 sep/end、f-string、基础运算与复合赋值、`input()` 转型、基础转义、比较运算与 and/or/not、if/else/elif/嵌套、while/break/continue、字符串方法（upper/strip/split/find 等在其所属章节内）、基础切片 `s[:3]`。

## 五、废弃执行流程 ——「正路」

> 红线：ECS 写操作前必须备份；写前只读核对 id 与 topic_id 一致（本地/ECS 可能不一致，曾误伤 #3758）。

```
Step 1  登录拿 admin token（POST /api/auth/login）
Step 2  备份（POST /api/admin/backup-db）★红线
Step 3  只读核对：SELECT id FROM questions WHERE topic_id=? AND deprecated=0
Step 4  写库：UPDATE questions SET deprecated=1 WHERE id IN (...)
        （POST /api/admin/exec-sql，逐条，script=False）
Step 5  回读验证：废弃计数=期望；活跃数=原活跃-废弃数
Step 6  本地与 ECS 两边逐题核对一致
```

复用脚本：`scripts/review_export.py`（按 topic 导出+完整性自检）、`scripts/deprecate_by_ids.py`（核对→备份→UPDATE→回读，双端对比）。纯数据变更不重建镜像、不重启。
